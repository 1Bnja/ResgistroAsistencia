💡 TIPS ÚTILES
═══════════════════════════════════════════════════════════════════════════

1. Siempre verifica el dashboard de HAProxy antes y después de hacer cambios:
   http://localhost:8404/stats

2. Para ver logs en tiempo real de múltiples contenedores:
   docker logs -f api-backend-1 &
   docker logs -f api-backend-2 &

3. Para detener todos los logs:
   killall docker

4. Para ver solo errores en los logs:
   docker logs api-backend-1 2>&1 | grep -i error

5. Para ver la distribución de requests en HAProxy:
   curl -s http://localhost:8404/stats | grep -A 5 "api_backend"

6. Para simular fallo completo de un servicio:
   docker pause api-backend-1  # Congela el contenedor
   docker unpause api-backend-1  # Descongela

7. Para forzar un health check failed:
   docker exec api-backend-1 pkill -9 node  # Mata el proceso
   # Docker lo reiniciará automáticamente

8. Ver tiempo de uptime de cada contenedor:
   docker ps --format "table {{.Names}}\t{{.Status}}"


═══════════════════════════════════════════════════════════════════════════
⚠️  NOTAS IMPORTANTES
═══════════════════════════════════════════════════════════════════════════

- Los servicios tardan ~10 segundos en estar "healthy" después de iniciarse
- HAProxy detecta fallos en ~5-10 segundos y redirige el tráfico automáticamente
- MongoDB Atlas (cloud) maneja su propia replicación, independiente de estos servicios
- Ambos api-backend son idénticos, no hay master/slave a nivel de aplicación
- El algoritmo de balanceo es Round-Robin (50/50) para todos los servicios
